# 주도주 스윙 콘솔 — 모바일 매매앱 구축 계획

> 개인용 매매 **의사결정 보조** 도구. 투자 자문이 아니며 주문 체결 기능은 포함하지 않는다.

## 0. 범위

| 범위 | 내용 | 상태 |
|---|---|---|
| **A. 의사결정 보조** | 스캔 · 지표 · 체크리스트 · 사이징 · 포지션 감시 · 알림 · 일지 | **채택 (v2)** |
| B. 반자동 주문 | 앱이 주문서를 채우고 사용자가 최종 전송 | 백테스트 검증 후 |
| C. 완전 자동매매 | 조건 충족 시 자동 주문 | 6개월 실전 검증 후 재판단 |

규칙의 기대값이 숫자로 검증되기 전에는 주문 자동화를 붙이지 않는다. 현재 체크리스트
가중치(`w`)는 근거가 없는 추정치이며, Phase 4 백테스트가 이를 대체한다.

## 1. 아키텍처

PWA를 유지한다. 네이티브로 전환하지 않는다 — 백그라운드 실행은 서버(Actions)가,
푸시는 텔레그램이 이미 해결하고 있어 네이티브 전환의 이득이 없다.

```
┌─ GitHub Actions (폰이 꺼져 있어도 동작) ─────────────────┐
│  06:30 미장 스캔 · 16:10 국장 스캔                        │
│  장중 15분 주기 포지션 감시 (POSITIONS_JSON 시크릿)        │
│      ↓                          ↓                        │
│  docs/*.json 커밋           텔레그램 푸시                  │
└──────────────────────────────────────────────────────────┘
                ↓ fetch (정적 JSON — CORS·키노출 없음)
┌─ 폰 / GitHub Pages PWA ──────────────────────────────────┐
│  오늘 · 차트 · 포지션 · 체크 · 일지  (하단 탭)             │
│  로컬 저장: IndexedDB                                     │
└──────────────────────────────────────────────────────────┘
```

**보안 원칙** — API 키·계좌 정보는 `docs/` 아래에 절대 두지 않는다. GitHub Pages는
공개 경로다. 비밀은 Actions Secrets에만 두고, 앱은 결과 JSON만 읽는다.

## 2. 영상 개념 → 계산 가능한 규칙

차트 개념을 숫자로 번역한 것이 이 앱의 실질 내용이다. 구현체는 `scanner/indicators.py`,
`scanner/patterns.py`이며 산출된 지표는 `results*.json`의 `metrics`에 실린다.

| 개념 | 지표 키 | 판정 |
|---|---|---|
| 위꼬리 / 아래꼬리 | `upper_wick_ratio`, `lower_wick_ratio` | `(고가−max(시,종))/(고가−저가)` |
| 적삼병 / 흑삼병 | `three_white_soldiers`, `three_black_crows` | 3연속 + 몸통 비감소 + 거래량 증가 |
| 20일선 = 생명선 | `close_vs_ma20_pct` | 이탈 시 포지션 경보 |
| 정배열 / 역배열 | `ma_aligned_bull`, `ma_aligned_bear` | KR 5>20>60>120 / US 50>150>200 |
| 골든 · 데드크로스 | `golden_cross_days`, `dead_cross_days` | 발생 경과일. 거래량 동반 여부 병기 |
| 이격도 | `disparity20`, `disparity20_pctile` | 절대 기준 대신 2년치 백분위 |
| 거래량 검증 | `vol_ratio_20` | **1.5배 미만이면 모든 신호를 회색 처리** |
| 고점 대량거래 경고 | `distribution_alert` | 고점 90%↑ + 거래량 2배↑ + 위꼬리 40%↑ + 변동폭 > ATR×1.5 |
| 지지 · 저항 | `sr_levels` | 250일 스윙 고저점 ±1.5% 클러스터, 3회 이상 접촉만 |
| 역할 전환 (리테스트) | `retest_level` | 돌파했던 저항선 재접촉 |
| 볼린저 밴드 | `bb_upper/mid/lower`, `bb_pctb` | MA20 ± 2σ |
| 스퀴즈 | `bb_squeeze`, `bb_width_pctile` | 밴드폭 126일 하위 20% 또는 중앙값의 절반 이하 |
| 밴드 워킹 | `band_state` | 상단 접촉 시 `walk`(MA20 상승+밴드확장) / `warn`(평탄+축소) |
| 컵앤핸들 | `cup_handle` | 깊이 12~33%, 7주↑, 손잡이 ≤15% 且 컵 중간값 위, 손잡이 거래량 < 베이스 70% |
| 쌍바닥 | `double_bottom` | 저점 간격 15일↑, 저점차 ≤3%, 저점2 거래량 < 저점1 |
| 헤드앤숄더 · 쌍봉 | `head_shoulders`, `double_top` | **매수 신호로 쓰지 않음. 보유 종목 청산 경보 전용** |
| 모닝 · 이브닝스타 | `morning_star`, `evening_star` | 3캔들 + 회복률 ≥50% |
| VCP 수축 | `vcp_contractions`, `vcp_vol_dryup` | 조정폭 순차 축소 + 마지막 구간 거래량 급감 |

**설계 원칙**: 패턴은 매수 신호가 아니라 **스캐너를 이미 통과한 후보의 가점**으로만
쓴다. 패턴 인식의 사후 확증·주관성 문제를 앱 구조로 차단한다.

## 3. 매매법의 코드화

체크리스트가 HTML에 하드코딩되어 있던 것을 JSON 룰셋으로 분리했다.

```
docs/rules/                 ← GitHub Pages 가 서빙하므로 앱이 직접 fetch 한다
├── us_minervini.json       Trend Template 8 + VCP 6
├── kr_leader.json          시장·수급 필터 6 + 대장주 트리거 6
└── exit_rules.json         손절·익절·추적·피라미딩을 숫자로
rules/
├── rules.py                조건 평가기 (Python — 스캐너·백테스트용)
└── schema.md               조건 DSL 명세
```

같은 JSON을 스캐너(Python)·앱(JS)·백테스트가 함께 읽는다. 규칙을 한 곳에서 고치면
세 곳이 동시에 바뀌므로 "체크리스트는 통과인데 스캐너는 안 잡는" 불일치가 사라진다.

각 항목은 `auto` 조건이 있으면 스캔 지표로 **자동 판정**되고, 없으면 사람이 판단한다.

| 구분 | 예시 |
|---|---|
| 자동 (18개) | 이평선 배열, RS, 52주 위치, 거래량 배수, 수급 연속 순매수, 거래대금 상위 유지 |
| 수동 (8개) | 테마 대장주 여부, 명확한 촉매, 오버행 공시, 시총 감당 가능성 |

## 4. 화면 (하단 탭 5개)

| 탭 | 내용 |
|---|---|
| **오늘** | 시장필터 신호등 → 스캔 후보 카드 → 오늘 할 일 |
| **차트** | 캔들 + MA + 볼린저 + 거래량 + 자동 지지/저항. 외부 라이브러리 없이 canvas 직접 구현 |
| **포지션** | 보유 종목 R배수 · 트레일링 스탑 · 피라미딩 다음 지점 |
| **체크** | 룰셋 체크리스트 (자동 항목 선반영) + R 사이징 |
| **일지** | 매매 기록 · 규칙 준수율 · 월간 통계 |

모바일 요건: 터치 타겟 44px, `env(safe-area-inset-bottom)`, 숫자 키패드,
외부 CDN 없음(오프라인 동작), IndexedDB 저장, 다크 기본.

## 5. 단계

| Phase | 내용 | 상태 |
|---|---|---|
| **0** | 룰셋 JSON 분리, CSS/JS 분리, 하단 탭, IndexedDB | ✅ 완료 |
| **1** | 지표 엔진 (`indicators.py`, `patterns.py`) + 스캐너 통합 | ✅ 완료 |
| **3** | 포지션 관리 — 피라미딩 · 트레일링 스탑 · 장중 감시 워크플로 | ✅ 완료 |
| **2** | 차트 탭 — canvas 캔들 + 지표 오버레이 | ✅ 완료 |
| **4** | 백테스트 — 룰셋 기대값 검증, 가중치 튜닝 | ✅ 완료 |
| **5** | 일지 통계 — 규칙 준수율, 패턴별 승률 | ⏳ 다음 |
| 6 | (선택) 반자동 주문 — KIS API, 모의계좌 → 소액 → 실계좌 | 보류 |

Phase 3까지가 실전 가치의 대부분이다. Phase 4를 건너뛰면 이 앱은 확증편향 도구가 된다.

### Phase 4 — 백테스트 (`backtest/`)

`docs/rules/*.json` 을 그대로 읽어 기대값을 실측한다. 백테스트용 규칙을 따로 두지
않으므로, 여기서 나온 숫자가 곧 실전에서 쓰는 규칙의 숫자다.

측정 항목 — 현행 룰셋 성과 / 기준선(고점근접+거래량만) 대비 개선 여부 /
core 항목별 탈락 비율 / 항목별 판별력(lift, |t|≥2) / 제안 가중치 /
과최적화 검증(유지율) / 파라미터 스윕.

방법론 — 룩어헤드 금지(t일 종가 판정 → t+1일 시가 체결), 갭 반영, 진입 당일 손절
검사, R 단위 손익. 국장은 시점별 종목 목록을 써서 생존편향이 없고 미장은 남아 있다.

실행 — Actions → **백테스트** → Run workflow. 결과는 `docs/backtest_<market>.md`
와 앱 일지 탭의 '룰셋 검증' 카드에 나온다. 자세한 내용은 `backtest/README.md`.

**가중치 반영 기준** — 검증기간 유지율이 60% 미만이면 그 가중치는 과거에만 맞는
숫자이므로 앱에 반영하지 않는다. 룰셋이 기준선을 개선하지 못하면 규칙을 단순화한다.

## 7. 알려진 리스크

1. **데이터 품질** — 수정주가 미반영·액면분할·상장폐지 누락이 백테스트를 통째로 왜곡한다.
   지표 계산 후 증권사 HTS 값과 3종목 이상 눈으로 대조하는 절차를 유지한다.
2. **자동 패턴 인식의 오탐** — 그래서 매수 신호가 아닌 가점으로만 쓴다.
3. **iOS PWA 캐시 정리** — 앱을 오래 열지 않으면 Service Worker 캐시가 비워질 수 있다.
   중요 알림은 반드시 텔레그램으로 보내고 앱은 조회용으로 둔다.
4. **포지션 데이터 위치** — 포지션은 폰의 IndexedDB에 있어 서버가 알지 못한다. 장중 감시가
   필요하면 앱의 "감시용 내보내기"로 생성한 JSON을 `POSITIONS_JSON` 시크릿에 붙여넣는다.
   공개 저장소에 포지션을 커밋하지 않는다.
